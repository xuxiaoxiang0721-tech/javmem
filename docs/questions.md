# 自己的题：拿问题量检索、量回答

写一份题（问题加上答这道题要用的原话），`javmem regress` 照现在的代码把账本重建一遍，每道题问一次，看那几句原话有没有进到给回答模型的那段上下文里（**证据命中率**）。不调付钱的模型：抽取用你存下的结果库，向量用本机的向量服务（或者假的）。换提示词、换模型、改检索以前和以后各量一次，就知道变好了还是变坏了。

题上再写标准答案的，还可以用 `javmem quiz` 让模型照查到的答一遍、再严格判一遍分（第 4 节；要调模型、花钱，可选）。整套怎么用见 [calibration.md](calibration.md)。

下面的例子取自仓库里那套编的小套件（`tests/fixtures/regress-mini/questions.json`，`javmem demo` 用的那 5 个包）。

## 1. 题的文件

题写成 JSON：

```json
{
  "format": "javmem-regress-questions/1",
  "from": "自己写的",
  "questions": [
    {"id": "M01", "category": "事实变化", "query": "梧桐路展厅项目现在谁负责？", "absent": false,
     "sources": ["2026-11-02_2300_demo-bot ｜ 梧桐路展厅项目从今天起改由田甜接手。"]},
    {"id": "M10", "category": "记忆里没有", "query": "我们和东湖酒店签过合同吗？", "absent": true, "sources": []}
  ]
}
```

| 字段 | 说明 |
| --- | --- |
| `id` | 题号，一份里不重复 |
| `query` | 问题，照平时真会问的样子写 |
| `sources` | 出处：答这道题要用到的原话，一条一个，写成“包号 ｜ 原话”。原话照包里的一字不差（空白不管），可以只是一句里的一段（至少 4 个字）；原话前面带着的“- [时间] 说话人：”会去掉再找 |
| `absent` | 记忆里没有的题写 `true`，出处空着。这种题不算命中率 |
| `category` | 类别，可以不写：简单回忆、关系串联、事实变化、数字条件、记忆里没有 |
| `answer` | 标准答案（`javmem quiz` 判分用，`javmem regress` 不看）：一两句，带上关键的名字、数、日子 |
| `accept` | 可接受的别的写法，一串，可以不写（比如 `["每吨 4500 元", "4,500 元一吨"]`） |
| `as_of` | 查询时间点：这道题当作哪天问的（`2026-11-10`），问“现在”的题要写；不写的当作今天问 |

出处要对得上账本里这个身份看得到的原句，对不上的那条不算（输出里“几条出处对上原句”会少）。

## 2. 怎么出题

- **五类都出一些：** 简单回忆（一句话就答得出）、关系串联（要把两三处连起来）、事实变化（以前是什么、后来改成什么，问“现在”）、数字条件（金额、日子、比例、条件）、记忆里没有（问一件包里没有的事，最好用一个相近的名字设个陷阱）。
- **出处要全：** 答这道题要的每一句都列上。漏了一句，那一句就算不进命中率。
- **问“现在”的题，**想好标准答案是哪天的：包里后来改过的，以后加了包可能又变。
- **分两份：** 一份调试用，调提示词、调检索的时候天天看；一份锁起来，平时不看、不拿来调，到最后要定版本的时候只跑一次。天天看着调的题，分数会越来越好看，不代表别的问题也答得好。

## 3. 拿 javmem regress 量

写一份套件文件（YAML），放在仓库外。路径写相对的，照套件文件所在的目录算：

```yaml
format: javmem-regress/1
name: 我的题
config:                        # 和平时写账用的一样
  JAVMEM_SOURCES_FILE: config/sources.yaml
  JAVMEM_ACCESS_FILE: config/access.yaml
  JAVMEM_OWNER_FILE: config/owner.yaml
  JAVMEM_LEXICON_FILE: config/lexicon.yaml
  JAVMEM_TIMEZONE: "+08:00"
retrieval:
  - line: 现在这一版            # 线的名字，随便起
    env: {JAVMEM_L3_PROMPT: l3-v17, JAVMEM_LLM_MODEL: 抽的时候用的模型}
    packets: [packets/*/*.md]  # 你的包
    store: data/l3/l3.db       # 抽的时候存下的结果库（只读，拷一份用）
    vectors: data/vectors/vectors.db   # 向量缓存（可以不写；缺的找本机的向量服务）
    questions: questions.json
    caller: 我的身份            # 用哪个身份问（身份表里的）
graph:
  mode: off                    # 主图那一路也要量的，见下面
baseline: baseline.json
```

- `env` 里的提示词、模型要和抽的时候一样：结果库照它们认窗口，对不上的报“要重抽”。
- 想比两版（比如换了提示词），用新的那一版另抽一遍、存进另一个结果库，套件里再写一条线。

第一次量，存成基准：

```bash
javmem regress --suite 我的套件.yaml --save-baseline --note "第一次量"
```

以后每次改了东西再量，和基准比：

```bash
javmem regress --suite 我的套件.yaml
```

每条线一行，比如编的小套件那一行“10 道题，10 / 10 条出处对上原句：……账本视图 9 / 9（基准 9 / 9），原文层 10 / 10”：

- **两个数：** 上下文放 5,000 字、1,500 字的时候，各有几条出处进去了。给回答模型的那段上下文就这么长，出处没进去，回答模型就看不到。
- **几路：** 账本视图（抽出来的事实、关系，加上它们的原话）、原文层（直接按字搜原话），开了主图的还有主图那一路。
- **“记忆里没有”的题**不算命中率。
- **题文件改了**（加题、删题、改出处），命中数就没法和基准比：重新存基准。
- `--exact`：一个数都不许变（只改了文档、只改了别处的代码时用）。

主图那一路也要量的：`graph` 那一段写 `mode: managed`（照 `deploy/graph-test-neo4j/compose.yaml` 起一个只给回归用的测试图，数据目录是回归自己的，用完停掉），或者 `mode: given`（用 `JAVMEM_GRAPH_TEST_NEO4J_URI` 写明的一个空图）。细节见 [development.md](development.md) 的“回归跑分”。

`javmem regress` 不调付钱的模型：要调的一步（抽取）用的是存下的结果库，向量用本机的服务或者缓存。它的工作目录、输出都在仓库外。

## 4. 让模型答一遍、判一遍分（javmem quiz，花钱）

命中率只说上下文里有没有那几句；回答模型拿着它们答得对不对，要真答一遍。`javmem quiz` 用 `JAVMEM_LLM_*` 配的模型（就是抽取在用的那个）先答、再判分，**每次调用都花钱**，记进 token 账。

```bash
javmem quiz --questions questions.json --out 仓库外的新目录 --dry-run        # 只检索、数要调几次、估多少 token
javmem quiz --questions questions.json --out 仓库外的新目录 --budget 200000  # 真答、真判
```

要先设 `JAVMEM_CALLER`：照这个身份看得到的检索，和 Bot 问的时候一样。一道题这样走：

1. 照问题检索，候选放进上下文（默认 1,500 字，`--context` 改），连同“现在是哪天”（题上的 `as_of`）交给回答模型。它只能照给的条目答，不够就说不知道。发出去以前和抽取一样挑过：private 的包里的条目不发，剩下的照打码模式表打一遍码。
2. 判分，一题只记一种：
   - **对**、**错**：判分模型照严格的提示词判。缺了关键信息、数错一位、给了几个候选、问现在答了以前的，都算错。
   - **规则先判：** 数字条件这一类，先比数和日子：标准答案（或者 `accept` 里任何一种写法）写到的数、日子，回答里都要有，一种都对不上就算错，不再问判分模型。万、亿、千分位换算以后比；写法精度不一样的（“约 3,729 万”和“37,286,519”），按粗的那一边四舍五入以后一样也算；日子只比月和日。
   - **不知道：** 回答模型说不知道。
   - **硬答：** 记忆里没有的题却答出了内容（说不知道才算对）。
   - **没答成**（调用失败、预算用完）、**没判**（没写标准答案）另记。
3. 出数：每类、总的各几道。

输出目录里：`summary.json` 只有数；`results.jsonl` 一题一行，有回答、判分的理由、上下文条目的编号；`calls.db` 存每一次调用的回复。同一个目录再跑一遍，问过的不再问、不花钱（换了题、换了上下文、换了模型的照样要问）。**这个目录里有原话：放仓库外，撤回、彻底删除管不到它，用完自己删。**

判分模型也会判错：答错的、影响大的题，打开 `results.jsonl` 自己再看一遍。`--fake` 用假模型走一遍流程，不连网、不花钱（分数没有意义）。
