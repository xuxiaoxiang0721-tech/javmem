# 记忆包规范 `javmem-packet/1`

javmem 对外只有两个口：写只认记忆包，读只走查询接口。这份规范管写：包长什么样、怎么投递、什么情况拒收。读的一侧见 [query-api.md](query-api.md)。

所有打包方都按这一份打包。收件时按它校验，不合格的不入库。旧的 1.2 格式不直接收，要先用 1.2 转换器转成本格式。

| 词 | 意思 |
| --- | --- |
| 打包方 | 写记忆包的程序：Bot，或者邮件导入工具 |
| 来源 | 登记过的打包方，一个来源一个编号，就是包头的 `source` |
| 来源目录 | 这个来源自己的收件目录：`inbox/<source>/` 和 `inbox-test/<source>/`，`<source>` 是来源编号 |
| 我 | 记忆的主人。原话里说话人写“我”，指的就是这个人 |
| 数据目录 | 配置项 `JAVMEM_DATA_DIR` 指向的目录。本文的目录都相对于它 |

本文的 Bot 名、人名、公司名、订单和邮箱都是编的。

## 1. 底线

1. **原话为主，摘要为辅。** 包里必须有原话。Bot 写的摘要可以有，但要标明是 Bot 写的；核对只认原话。
2. **每句话都有时间和说话人。** 谁说的、什么时候说的，是后面分辨“我说的”和“Bot 建议的”、换算“下周”这类时间的依据。
3. **一个来源一份包。** 每个来源各写各的，不替别的来源汇总。带敏感标记的材料不经过别的来源转手。
4. **只有登记过的来源能投递，各投各的目录。** 不在登记表里的一律拒收。所在目录和包头 `source` 对不上的也拒收，这样投错目录、写错来源进不了库。防故意冒充还要靠给每个来源的目录配各自的系统写权限，同一个系统用户下防不住，见第 11 节。测试中的来源只投测试目录。
5. **只通过收件目录写入。** 先写临时文件再改名移进自己的来源目录。打包方和管理员都不直接改库，javmem 是唯一的写入方。

## 2. 什么时候封包

**模块不管多久打一次包。** 每晚一次、每小时一次、有事才打都行，这是打包方自己的事。模块只看包本身合不合规。

一个包装一个来源在一个时间段里的内容。每包写明覆盖哪段时间，下一包从上一包结束的时刻接着来，不漏不重。

| `kind` | 什么时候用 | 怎么写 |
| --- | --- | --- |
| `daily` | 例行的包，不管实际多久打一次 | 覆盖从上一个例行包结束到这次封包 |
| `adhoc` | 定了要紧的事（决定、换人、金额），想马上进记忆 | 只装这段内容；之后的例行包不再重复这段 |
| `backfill` | 补历史记录 | 按原来的日期分包，写原来的时间 |

- **一段对话一个小节。** 一包里有几段对话，每段一个原话小节。一段对话中间停了 30 分钟以上，就算两段。
- **太长就拆。** 原话超过 2 万字，按对话拆成几个包。后一包的 `continues` 写前一包的编号，`covers_from` 接前一包的 `covers_to`。
- **没有内容不发空包。**
- **测试中的来源一样封包，** 只是 `env` 写 `test`，投测试目录。
- **不同权限的内容分开打。** 分区和敏感标记打在整个包上，身份能看包的其中一个分区，就看得到整个包（第 13 节）。想挡住的内容不要和别的分区打在一个包里，或者打敏感标记。要分开，就打成几个包，这几个包的时间段可以相同，重名时按第 4 节加 `_2`。

## 3. 包的结构

一个包是一个 UTF-8 的 Markdown 文件：开头是 YAML 头，后面是一个或几个原话小节，再后面可以跟摘要和附件小节。

```text
---
包头字段，见第 4 节
---

## 原话 · ……         必须有，可以有多个
## 摘要（Bot 写的）    可选
## 附件               可选：附件的说明和正文，见下面“附件小节”
```

小节靠行首的二级标题认：`## 原话` 开头的是原话小节，`## 摘要` 开头的是摘要小节，`## 附件` 开头的是附件小节。认不出的二级标题记一条警告，它下面的内容不进原文索引，归档里还在。

包有两种，由包头 `channel` 决定：`chat` 是对话包，原话写法见第 5 节；`email` 是邮件包，见第 6 节。

### 附件小节

附件小节放两样东西：Bot 写的说明，和附件的正文。

**说明**写在小节开头，一行一条，比如 `- 图片说明：一张价格表，单价 12.5 美元。`。说明是 Bot 写的，不是附件的原文。

**正文**一个附件一块，接在说明后面：

````text
### 附件 · 报价单.pdf

```yaml
name: "报价单.pdf"
type: "application/pdf"
size: 48213
of: {section: 2}
text: full
```

  示例家居公司 订货确认
  木纹色餐桌 2000 件，交货期 2026-11-15，含包装。
````

- 一块从行首的 `### ` 开始，后面写附件名，只给人看。下面先是一段 `yaml` 围栏，空一行后是正文，到下一个 `### ` 或者小节结尾为止。
- 正文每行前面加两个空格，空行可以不加，和邮件正文一样：附件里写什么都变不成包的结构。
- 不读、读不了的附件也写一块，只写 yaml，不写正文，记下名字和原因。
- 一块写错了（围栏不全、缺必填的、取值不对、`of` 指不到）不拒收，记一条警告进巡检（第 12 节），这一块不进原文索引、不算行数，归档里还在。

| 字段 | 必填 | 取值 | 说明 |
| --- | --- | --- | --- |
| `name` | 是 | 文本 | 附件名，压成一行、打过码 |
| `type` | 是 | 文本 | 类型，比如 `application/pdf`、`image/png` |
| `size` | 否 | 整数 | 文件多少字节 |
| `of` | 是 | 对话包 `{section, line}`，邮件包 `{section}` | 附件属于哪句话、哪封信。对话包是提到它的那句话的 `position`：第几个原话小节的第几句话；邮件包是第几封 |
| `text` | 是 | `full` / `truncated` / `none` | 正文全收了、只收了一部分、没收 |
| `reason` | `truncated`、`none` 必填 | 见下面的表 | 为什么只收了一部分、为什么没收 |

**哪些读正文，怎么转成文字：**

| 附件 | 怎么读 |
| --- | --- |
| 纯文字：`text/plain`、`text/csv`、`text/tab-separated-values`、`text/markdown` | 按声明的编码解；没声明的先试 UTF-8，再试 GB18030，最后 latin-1 |
| HTML：`text/html` | 和 HTML 邮件一样转成纯文字（第 6 节） |
| PDF：`application/pdf` | 只取文字层，不做文字识别。加了密的：要密码才打得开、或者写着不许提取文字的不读；不用密码能打开、也没写不许提取的照读。读出来是乱码的页不收：字体没有对照表，一页里一半以上的字读成了符号、私用区的字或者 `(cid:12)` 这种占位 |
| Excel：`.xlsx`、`.xlsm`、`.xls` | 只取单元格的值，不取公式：公式取文件里存着的算好的值，没存的是空的。一个工作表一段，先写 `[工作表 名字]`，再一行一行写，格子之间用 tab；空行、一格字都没有的表不写。数照 Excel 显示的写（最多 15 位有效数字），只有时刻的写时刻，错误值写 `#DIV/0!` 这样；一行里同一列写了两格的（坏文件）只写后面那个，和 Excel 一样。要密码才打得开的不读 |
| Word：`.docx` | 正文的段落和表格按原来的先后写：内容控件里的、插入的修订、域的结果都是正文；还没填的内容控件里显示的提示字（“单击此处输入文字”这类）不读，整格没填的那一格写空，后面的格子不往前挪。表格一行一行写，格子之间用 tab，合并的格子只写一次，格子里套着的表格连成一格；一段里连着 9 个以上的空格写成一个。页眉、页脚、脚注、批注、文本框、删掉的修订、域代码、注音不读；同一样东西有几种写法的（`mc:AlternateContent`）只读第一种。要密码才打得开的不读。老的 `.doc` 先不读 |
| 图片和别的类型 | 不读，只记名字 |

- 类型按 `type` 认。写的是 `application/octet-stream` 这类说不清的，再看扩展名；写着 Excel、Word 的类型、扩展名却是纯文字、网页的（Windows 把 `.csv` 记成 `application/vnd.ms-excel`），按扩展名读。
- 转出来的文字换行统一成 LF，换页符这类分隔换成换行，每行去掉行尾的空白，连着的空行只留一个。别的照录，不改写、不总结、不翻译。
- **太大的：** 文件超过 20 MB 不打开，`text: none`、`reason: too_large`；xlsx、docx 解开以后超过 200 MB、又比文件本身大 50 倍以上的也是（压缩炸弹；xlsx 里工作簿写明、别处也没写成别的东西的工作表边解边读，不算）。转出来的文字超过 2 万字，在 2 万字以内的最后一个换行处截断；那个换行离 2 万字太远、截下来不到一万字的（一格、一段特别长），在 2 万字处截，往回找最近的空格（最多 200 个字）；截点落在一串值里（密码、密钥、base64 这类，带着 `@`、`#` 这些符号的也算）的，退到这一串前面，不留半截值；从头就是一整串、要退到一半以前的，照原来的截点截。都记 `text: truncated`、`reason: too_long`。PDF、Excel、Word 读了 60 秒还没读完的不收，`reason: timeout`：几 KB 的文件就能故意做成要读几个小时的（xlsx、docx 是压缩包，几 KB 能解出几 GB）。附件的正文不算进第 2 节的 2 万字。

| `reason` | 意思 |
| --- | --- |
| `too_long` | 转出来超过 2 万字，截断了 |
| `garbled` | PDF 里有几页读出来是乱码，没收那几页，别的页收了 |
| `too_large` | 文件超过 20 MB，或者 xlsx、docx 是压缩炸弹（解开以后超过 200 MB，又比文件本身大 50 倍以上），没打开 |
| `image` | 图片，不读 |
| `encrypted` | 加了密：要密码才打得开，或者写着不许提取文字 |
| `no_text` | 没读出字：扫描件，每一页都是乱码，或者表格、文档里一个字都没有 |
| `timeout` | 读了太久还没读完，没收 |
| `unsupported` | 别的类型，不读；老的 `.doc` 也是 |
| `unreadable` | 文件坏了，读不了；写着是 Excel、Word，文件却不是 |
| `missing` | 打包方拿不到这个文件 |

**打码照样过：** 附件名和正文都按第 7 节打码，收件时也一样扫（第 12 节）。

**分区和敏感标记跟着包走：** 附件和它属于的那句话、那封信在同一个包里，分区和敏感标记就是这个包的（第 13 节），邮件往来串往后传的敏感标记（第 6 节）也一样带上。不想让附件和这段对话一样的人看得到，按第 2 节拆包或者打敏感标记。

**进原文层和查询结果：**

- 正文一句一句进原文索引，分句和原话一样，`> ` 开头的行也一样算引用。编号是 `包号#attachment.行.句`，`position` 是 `{section: "attachment", line, sentence}`（query-api 4.5）。`line` 是附件小节里的第几行，说明和正文连着数，空行、`### ` 那一行和 yaml 都不算。
- `origin` 是 `external`：附件的内容按外部内容算（第 5 节），只靠附件撑着的事实是转述（query-api 4.2 的 `secondhand`）。说明还是 `attachment_note`。
- 说话人和时间跟着它属于的那句话、那封信：对话是那句话的说话人和时间，邮件是发件人和 `date`，查询结果里还带那封信的 `email`。
- 它属于的那句话、那封信整个撤回了（引用行不算），附件也一起撤回（query-api 3.2）；写着附件名的那一句撤回了也一样，邮件是邮件头的附件名那一句。

## 4. 包头字段

| 字段 | 必填 | 取值 | 说明 |
| --- | --- | --- | --- |
| `schema` | 是 | `javmem-packet/1` | 规范版本。别的值都认不出，拒收 |
| `packet_id` | 是 | `YYYY-MM-DD_HHMM_<source>`，重名加 `_2`、`_3` | 包号。同一个包重发用同一个编号 |
| `created_at` | 是 | 带时区的时间 | 封包时间 |
| `source` | 是 | 登记表里的来源编号 | 不在登记表里的拒收 |
| `framework` | 是 | 小写英文、数字和连字符 | 打包方跑在哪个框架上。只作记录，模块不按它分支 |
| `channel` | 是 | `chat` / `email` | 对话包还是邮件包。要和登记表一样 |
| `env` | 是 | `prod` / `test` | `test` 只能进测试目录 |
| `kind` | 是 | `daily` / `adhoc` / `backfill` | 见第 2 节 |
| `covers_from`、`covers_to` | 是 | 带时区的时间，前者不晚于后者 | 这包覆盖的时间段 |
| `domain` | 是 | 非空列表：`business` / `finance` / `investment` / `research` / `dev` / `personal`，可以在配置里加别的 | 查询时变成分区，身份能看其中一个就看得到整个包。财务、投资的严格规则也按它触发：包的分区里只要有一个是严格分区就触发。哪些分区算严格写在配置里，默认 `finance` 和 `investment` |
| `privacy` | 是 | `normal` / `private` | 现在一律写 `normal`。字段留作以后的例外通道：`private` 的不上云，走本地模型 |
| `sensitive` | 否 | 列表，不写等于空列表。每一项都要在这个来源的 `may_carry` 里。`private` 是保留字，不能写 | 敏感标记，打在整个包上。不想整包受限就拆包。查询时只回给配置里写明能看这个标记的身份 |
| `entities` | 否 | 标准名列表 | 能读到 javmem 导出的标准实体名单时才填。名单也按身份过滤：只导出这个来源同名的查询身份看得到的实体，没有同名身份就不给 |
| `continues` | 否 | 上一包的 `packet_id` | 拆包或接续时填 |
| `revision` | 否 | 从 1 起的整数，不写等于 1 | 同一个包改了内容重发时加一，见第 10 节 |
| `mailbox` | 邮件包必填 | 邮箱地址 | 这包来自哪个邮箱，要和登记表一样。对话包不写 |

**带时区的时间：** ISO 8601，必须带时区偏移，比如 `2026-11-08T23:30:00+08:00`。没带时区的算取值不合规。

**`packet_id` 怎么取：**

- 日期和时分取 `covers_to`，按 `covers_to` 自己的时区。这样改内容重发时编号不变。
- `<source>` 部分和 `source` 字段一样。
- 文件名就是 `packet_id` 加 `.md`。重名时 `packet_id` 和文件名一起加 `_2`、`_3`。
- 写成正则：`^\d{4}-\d{2}-\d{2}_\d{4}_[a-z0-9]+(-[a-z0-9]+)*(_[1-9]\d*)?$`

## 5. 对话包的原话

原话小节的标题写成 `## 原话 · 10:30–10:52`，标题里是这段的起止时间，只给人看，起止之间用 `–`，也认 `-`。跨天的写全日期：`## 原话 · 2026-11-07 23:58–2026-11-08 00:12`。

下面一句一行：时间、说话人、原文。

```text
原话行   - [时间] 说话人：原文
时间     HH:MM 或 YYYY-MM-DD HH:MM
续行     两个空格开头，接在上一句后面
引用行   两个空格加 > [引用 时间 说话人] 原文，接在回复的那句后面
```

| 情况 | 写法 | 说明 |
| --- | --- | --- |
| 普通一句 | `- [10:42] 我：越南那批订单推迟到 11 月 5 日出货` | 时间到分钟；“我”就是记忆的主人 |
| Bot 说的 | `- [10:43] desk-bot：要不要让老周也盯一下出货？` | 用来源编号。Bot 的建议、复述、算出来的数也要录 |
| 别人说的 | `- [10:45] 小李：客户同意了` | 群聊里用显示名 |
| 日期不是 `covers_to` 那天 | `- [2026-11-07 23:58] 我：……` | 写全日期 |
| 一句话有好几行 | 第二行起缩进两格 | 不拆成几句 |
| 引用 | `> [引用 10:30 我] 越南那批还是小李跟` | 回复里引用的旧话，不算新说的。写在回复的那句下面，缩进两格 |
| 转发 | `- [10:40] 我：[转发 自 小李] 客户说可以推到 15 号` | 转发的内容按转述处理 |
| 外部内容 | `- [10:41] desk-bot：[外部:网页] 海运 11 月中旬运力紧张` | 网页、搜索、文件、邮件、工具返回都标外部，只录必要片段 |
| 语音 | `- [10:50] 我：[语音] ……` | 转写的文字，可能有错 |
| 图片和文件 | `- [10:51] 我：[图片:报价单.jpg]`，`- [10:51] 我：[文件:合同.pdf]` | 说明和正文写在“附件”小节（第 3 节），`of` 指着这句话 |
| 撤回和编辑 | 撤回的不录；编辑过的录最后一版 | |
| 打码 | `[已隐去:密码]` | 哪些要打码见第 7 节 |
| Bot 问待确认 | `- [10:44] desk-bot：越南那批记着是小李负责，前天你说是老周，按老周改吗？（待确认 Q3F9A1C）` | 编号原样写在问的那句话里，见第 7 节第 10 条；主人的回答照常录 |

校验和解析按这些规矩：

- 只写 `HH:MM` 的行，日期取 `covers_to` 那一天，时区也跟 `covers_to` 一样。
- 说话人到第一个冒号为止。说话人后面写全角冒号 `：`，半角 `:` 也认。
- 说话人是 `我`、来源编号或显示名。显示名和 `我`、来源编号撞了，或者里面有冒号，打包方要改写，比如加个后缀。
- 行首的 `[转发 自 某人]`、`[外部:类型]`、`[语音]` 管这一整句话，包括同一行后面的句子和续行。
- 一个小节一句合规的原话都没有，不算原话小节。

下面这些不拒收，记一条警告，进巡检（第 12 节）：

- `- [` 开头却解析不了的行：不并进上一句，不进原文索引，也不抽取，归档里还在。不能让一句话算到别人头上。说话人里带方括号（`[`、`]`）的行也算解析不了，多半是漏写了说话人。
- 别的认不出的行：算上一句的续行。小节开头就认不出的不进原文索引，归档里还在。
- 时间倒退：整包按顺序读，后面的时间比前面早，可能是日期写错了。

## 6. 邮件包

邮件包把一个邮箱一段时间的邮件打成一个包，由导入工具从 `.eml`、`.mbox` 转出来。投递、拒收、去重都和对话包一样，不一样的是下面这些。

**包头：** `channel` 写 `email`，`mailbox` 写这个邮箱的地址，`framework` 写 `mail-import`。一个邮箱一个来源。

**小节：** 一封邮件一个原话小节，标题写 `## 原话 · 邮件 · 2026-11-03 09:12`，时间用这封邮件自己的时区，只给人看。标题下面先是一段 `yaml` 围栏写邮件头，空一行后写正文。

| 邮件头字段 | 必填 | 取值 | 说明 |
| --- | --- | --- | --- |
| `message_id` | 是 | 邮件头 `Message-ID` 原样，带尖括号 | 这封邮件的编号，跨包、跨邮箱都不变。原信没有时，导入工具按内容生成 `<generated-内容哈希@javmem.invalid>` |
| `thread_id` | 是 | 字符串 | 往来串编号，同一串相同，跨包也相同 |
| `in_reply_to` | 是 | 回复的那封的 `message_id`，不是回复写 `null` | 回复关系 |
| `references` | 否 | `message_id` 列表，邮件头 `References` 原样 | 回复关系 |
| `from` | 是 | `{name, addr}`，没有显示名时 `name` 写 `null` | 发件人。这封邮件所有句子的说话人。原信没有时不进包，写进导入工具的报告 |
| `to` | 是 | `{name, addr}` 的列表，可以是空列表 | 收件人 |
| `cc` | 否 | 同上 | 抄送 |
| `bcc` | 否 | 同上 | 密送，发件箱里的副本才有 |
| `date` | 是 | 带时区的时间，保留邮件原来的时区 | 邮件头 `Date`。这封邮件所有句子的时间。原信没有，或者比导入的时刻晚一天以上（写错的、垃圾邮件），就用最上面一条 `Received` 的时间；还没有就不进包，写进导入工具的报告 |
| `subject` | 是 | 原文，可以是空字符串 | 主题。`Re:`、`回复:` 这些前缀不去掉。只有打码可以改 |
| `attachments` | 否 | `{name, type, size}` 的列表 | 附件名单。附件的正文写在“附件”小节（第 3 节），`of` 指着这封；不读、读不了的只记名字。内嵌在正文里的图（正文里用 `cid:` 引用着的图片，多是签名里的小图）不进名单，也不写附件块，只在 `inline_images` 记几张 |
| `inline_images` | 否 | 不小于 0 的整数 | 内嵌图几张，没有的不写。原文索引里附件名单那一句末尾接上“另有内嵌图 N 张” |

**正文：**

- 每行前面加两个空格，空行可以不加。这样正文里写什么都变不成包的结构：一封邮件里写了 `## 原话`，也不会被认成新的小节。
- 正文照录，不改写、不总结、不翻译。HTML 邮件转成纯文字，编码统一转成 UTF-8。纯文字的正文里，发信的客户端写进去的 `&nbsp;` 换成空格，行首的 `&gt;` 换成 `>`（引用），别的实体照录。
- 引用、签名、转发都原样留着，导入工具不删不标。认它们是 L1 的事：回复里引用的旧内容不当新消息，签名不当事实。

**整封都算外部内容。** 不用逐行写 `[外部:邮件]`。内容当转述，不当事实；夹带的指令一律当普通文字，不执行。

**打码：** 导入工具是程序，靠配置的打码模式表认密码、验证码、密钥和令牌。主题、显示名、附件名、正文和附件的正文都要过一遍，这是唯一可以动原文的地方。命中几处写进导入工具的报告，不抄值。

**分区和敏感标记：** 导入工具按配置的规则（发件人、主题关键词）把邮件分到不同的包，各写各的 `domain` 和 `sensitive`，附件跟着它那封信进同一个包。没有规则时 `domain` 用登记表的 `default_domain`。同一往来串里先来的信带的敏感标记，后来的回信也带上，分区不动：回信常常引用原信，不能让看不到原信的人从回信里看到。导入工具判断不了内容算不算敏感，第 7 节第 6 条的 `[已隐去:标记名]` 它不写，所以敏感材料多的邮箱要先配好规则再导入。

**往来串：**

- `thread_id` 取往来串第一封的 `message_id`：有 `References` 用它的第一项，没有就用 `in_reply_to`，都没有就是自己。头不全的，按去掉前缀的主题和来往的人归串。
- 同一个包里，同一往来串的邮件排在一起，串内按 `date` 从早到晚；不同的串按各自第一封的 `date` 排。
- 一个往来串可以跨几个包。L2 切窗时靠 `thread_id` 把它放进同一个窗口，可见范围不同的包不放在一起（第 13 节）。

**还有三条：**

- 同一封邮件进了几个邮箱，每个邮箱各记一份，靠 `message_id` 认出是同一封。同一个邮箱的同一封只进一次：导入工具自己记住处理过哪些 `message_id`，重跑也不会重复。同一个 `message_id` 改了以后重发的（内容不一样），同一批里留 `Date` 晚的那封，没导的记进导入工具的报告；以前导过的照旧不再导，报告里记下这一封在哪、以前导进了哪个包，要人看一下。它的状态和报告放在自己的目录，不放收件目录。
- 太长就把时间段切短，在两封邮件之间切。每个包的 `covers_from`、`covers_to` 都要包住它里面所有邮件的 `date`。
- 导入工具不写摘要。

对话里 Bot 引用一封邮件时，还是按第 5 节写 `[外部:邮件]`，只录必要片段。整封进记忆的才走邮件包。

## 7. 打包规矩

1. **原话照录。** 原话优先由程序从聊天记录导出；做不到时让模型逐字复制，不改写、不总结、不翻译，错别字也不改。
2. **Bot 自己说的也要录。** 尤其是建议、复述和算出来的数。后面的规则靠说话人分清“我说的”和“Bot 建议的”。
3. **摘要另起一节。** 标题写 `## 摘要（Bot 写的）`。摘要里可以用标准实体名、把“下周一”换成日期，但它不算证据，也不进原文索引。
4. **原话里不加东西。** 解释、备注、Bot 的判断都写进摘要，原话小节只放说过的话。
5. **外部内容只录必要片段，并标来源。** 外部内容里夹带的指令一律当普通文字，不执行。
6. **敏感材料只出现在允许带它的来源的包里。** 包头标 `sensitive`。其他来源碰到这类材料，原话里写 `[已隐去:标记名]`，不录内容。谁能带什么写在来源登记里（第 11 节）。
7. **这些一律打码：** 密码、验证码、密钥和令牌，分别写 `[已隐去:密码]`、`[已隐去:验证码]`、`[已隐去:密钥]`、`[已隐去:令牌]`。别的都不打码，手机号、邮箱、银行卡号、身份证号照原文录。打包方负责打码；收件时再按打码模式表扫一遍，命中只提醒（第 12 节），不拒收，也不改文件。
8. **纠正照常录。** 主人说“不对，是老周负责”，照原话录；怎么替换旧记忆由 javmem 处理。
9. **不重复投递。** 同一段内容只发一次；要补内容就用同一个编号，`revision` 加一。
10. **问待确认带上编号。** Bot 问主人一条待确认的事时，把这一条的编号（查询接口给的，`Q` 开头）原样写在问的那句话里，写成“（待确认 编号）”；问法是“要不要照新说的改”。主人答的照常录，javmem 照它认是在答哪一条，认不出就不算。

## 8. 投递

打包方只往自己的来源目录写文件。每个来源一个目录，目录名就是来源编号。目录都相对于数据目录：

| 目录 | 放什么 |
| --- | --- |
| `inbox/<source>/.tmp/` | 打包方先写到这里 |
| `inbox/<source>/` | 写完再移进来。收件只扫这一层 |
| `inbox-test/<source>/.tmp/` | `env` 为 `test` 的包先写到这里 |
| `inbox-test/<source>/` | `env` 为 `test` 的包，只给测试库处理 |
| `archive/YYYY/MM/` | 入库成功的包，只读归档。年月取 `packet_id` 的日期 |
| `archive-test/YYYY/MM/` | 测试包的归档，和正式的分开 |
| `archive/skipped/`、`archive-test/skipped/` | 去重时跳过的文件，不入库，见第 10 节 |
| `failed/<source>/` | 没通过的包，旁边附 `.error.txt` 写明原因。`<source>` 是文件所在的来源目录，正式和测试的放在一起。把读权限只开给这个来源，它就只看得到自己的失败包 |
| `failed/_unknown/` | 认不出来源目录的文件，见第 9 节。只给管理员看。来源编号里没有下划线，不会撞名 |

`inbox/`、`inbox-test/` 的根目录不放文件，放了就拒收。归档不分来源，包号里就有来源。

**怎么写：**

1. 文件名就是 `packet_id` 加 `.md`。
2. UTF-8 编码，最好不带 BOM，带了也认；换行符用哪种都行。
3. 先写进来源目录下的 `.tmp/`，写完再移进来源目录，这样不会读到写了一半的文件。`.tmp/` 和来源目录要在同一个磁盘上，移动才是一步完成的。
4. 打包方的本地写权限只开到自己的来源目录和它下面的 `.tmp/`，不碰本机其他文件和别的来源的目录。

**收件的顺序：** 扫每个来源目录这一层的 `.md` 文件（`.tmp/` 不扫）→ 校验（第 9 节，放错位置的也在这里拒收）→ 去重（第 10 节）→ 写包登记 → 归档 → 建原文索引 → 排队抽取。原文索引不等抽取，包一到几分钟内就能查到。

**中断了不丢包：** 每一步都能重做。启动时对账收件目录、归档和包登记，没做完的接着做。

**从原文重跑只按包登记走：** 按包登记找现行的包，不按文件扫归档目录。`skipped/`、留档的旧版和撤回的包都不算。

## 9. 拒收

下面六种情况拒收，文件移进 `failed/`，不入库。

先看文件放的位置：直接放在 `inbox/`、`inbox-test/` 根目录的，或者所在目录不在登记表里的，不读内容，按第 2 条拒收。位置没问题的先查编码，其余按表里的顺序查，查到第一条就停。第 1 条里和登记表有关的几项（`channel`、`mailbox`、`may_carry`），在第 2 条过了之后才查。

| # | 错误码 | 情况 | 包括 |
| --- | --- | --- | --- |
| 1 | `bad_header` | 缺必填字段，或者 `schema` 认不出 | YAML 头解析不了；字段取值不合规（`env`、`kind`、`channel`、`privacy`、`domain` 不在允许范围，时间没带时区，`covers_from` 晚于 `covers_to`）；`packet_id` 格式不对，或者和文件名、`source` 对不上；`channel`、`mailbox` 和登记表不一样；`sensitive` 里有这个来源 `may_carry` 之外的标记；邮件包缺 `mailbox`，或者某封邮件缺必填的邮件头字段 |
| 2 | `unknown_source` | 认不出来源：`source` 不在登记表里，或者和所在的来源目录不一样 | 文件直接放在 `inbox/`、`inbox-test/` 根目录；所在目录不在登记表里 |
| 3 | `env_mismatch` | `env` 是 `test`，却投进了正式的 `inbox/<source>/` | `env` 是 `prod` 却投进了 `inbox-test/<source>/`；登记为 `test` 的来源，包头写 `prod` |
| 4 | `no_raw_section` | 没有原话小节 | 有 `## 原话` 标题，但一句合规的原话都没有。邮件包只要邮件头齐全就算一封，正文可以是空的 |
| 5 | `time_out_of_range` | 原话里的时间落在 `covers_from` 到 `covers_to` 之外超过一天 | 引用行不算，它引的本来就是旧话。邮件包查 `date` |
| 6 | `not_utf8` | 文件不是 UTF-8 | 按严格 UTF-8 解码，带 BOM 不算错 |

放的位置怎么算，用第 11 节的登记表举例：

| 文件放在 | 包头 | 结果 | 移到 |
| --- | --- | --- | --- |
| `inbox/desk-bot/` | `source: desk-bot`，`env: prod` | 位置对，接着查别的 | |
| `inbox-test/desk-bot/` | `source: desk-bot`，`env: test` | 位置对，接着查别的 | |
| `inbox/desk-bot/` | `source: books-bot`，`env: prod` | `unknown_source` | `failed/desk-bot/` |
| `inbox/desk-bot/` | `source: desk-bot`，`env: test` | `env_mismatch` | `failed/desk-bot/` |
| `inbox-test/desk-bot/` | `source: desk-bot`，`env: prod` | `env_mismatch` | `failed/desk-bot/` |
| `inbox/trial-bot/` | `source: trial-bot`，`env: prod` | `env_mismatch` | `failed/trial-bot/` |
| `inbox/` 根目录 | 不看 | `unknown_source` | `failed/_unknown/` |
| `inbox/no-such-bot/` | 不看 | `unknown_source` | `failed/_unknown/` |

失败的文件放 `failed/<source>/<原文件名>`，说明放旁边的 `failed/<source>/<原文件名去掉 .md>.error.txt`。这里的 `<source>` 是文件所在的来源目录，不看包头：包头可能写错，也可能是冒充。认不出来源目录的放 `failed/_unknown/`。同名时都加 `_2`、`_3`。说明文件长这样，不抄原文内容，只写行号：

```text
code: time_out_of_range
file: 2026-11-08_2330_desk-bot.md
inbox: inbox/desk-bot
checked_at: 2026-11-08T23:31:05+08:00
detail: 第 12 行的时间 2026-11-01 10:42 早于 covers_from 超过一天
```

## 10. 去重和 revision

同一个包改了内容重发：用同一个 `packet_id`，`revision` 加一。不写 `revision` 等于 1。正式库和测试库各算各的。

设这个 `packet_id` 现在收下的版本是 C，新来的是 R：

| 情况 | 怎么办 |
| --- | --- |
| 没收过这个 `packet_id` | 正常入库 |
| R 等于 C | 直接跳过。内容和已收的不一样时巡检提醒：要么是改了内容忘了加 `revision`，要么是两个不同的包撞了号，要人看一下。不能一律加 `revision`，那样会把前一个包替换掉 |
| R 大于 C | 新包替换旧包，旧包留档 |
| R 小于 C | 跳过，这是晚到的旧版本 |

**跳过的文件** 移进 `archive/skipped/`（测试包是 `archive-test/skipped/`），同名加 `_2`、`_3`，不入库，不算拒收。

**进了 `failed/` 的不算收过。** 修好了直接重投，不用加 `revision`。

**替换时做这些：**

1. 旧包在归档里改名成 `<packet_id>.r<C>.md` 留档，新包放到 `archive/YYYY/MM/<packet_id>.md`。
2. 原文索引换成新包的。
3. 旧包派生的事实和关系按撤回的规矩清掉：只删完全来自它的，其他来源也支持的用剩余原文重建。
4. 新包重新走处理线。

**替换不动这三样：** 冻结的事实、主人定过的待确认、单条撤回的记录。新包和它们冲突的进待确认；单条撤回的内容不会因为替换又回来。

替换以后，查询只看最新版本，证据里写的 `revision` 也是最新的。旧版留在归档里，如果旧版里有没打码的密钥，只加 `revision` 不够，要用管理命令物理删除旧版。

**撤回过的包号不再收。** 不管 `revision` 多大都跳过，巡检提醒。撤回是管理操作，打包方重发解除不了；要重新进记忆，走管理命令解除。

## 11. 来源登记和新来源接入

只有登记表里的来源能投递。登记表写在配置里，由配置项 `JAVMEM_SOURCES_FILE` 指定，真实的登记表放仓库外。代码里不写死任何 Bot 的名字。

```yaml
domains: [business, finance, investment, research, dev, personal]  # 可选，不写就是这六个
sources:
  desk-bot:
    note: 日常用的 Bot
    framework: demo-chat
    env: prod
    channel: chat
    default_domain: [business]
    may_carry: []
  books-bot:
    note: 管账的 Bot
    framework: demo-chat
    env: prod
    channel: chat
    default_domain: [finance]
    may_carry: [payroll]
  trial-bot:
    note: 还在试的 Bot，只投测试目录
    framework: demo-chat
    env: test
    channel: chat
    default_domain: [business]
    may_carry: []
  mail-sales-a:
    note: 业务员 A 的邮箱
    framework: mail-import
    env: prod
    channel: email
    mailbox: li.ming@example.com
    default_domain: [business]
    may_carry: []
```

| 字段 | 说明 |
| --- | --- |
| 来源编号 | 小写英文、数字和连字符，定了就别改：它会写进每个包和每条记忆的来源，也是它的来源目录名 |
| `note`、`framework` | 说明和框架，只作记录 |
| `env` | `test` 的来源只能投 `env: test` 的包。`prod` 的来源也可以投 `env: test` 的包来试跑 |
| `channel`、`mailbox` | 包头要和这里一样 |
| `default_domain` | 给打包方的参考，包头的 `domain` 才算数 |
| `may_carry` | 这个来源能带哪些敏感标记。一个标记只要写进了某个来源的 `may_carry` 就算登记过 |

**防得住和防不住的：**

| 情况 | 防得住吗 | 靠什么 |
| --- | --- | --- |
| 投错目录、包头写错来源 | 防得住 | 收件时核对目录和 `source`，对不上的拒收 |
| 故意冒充别的来源：往它的目录写，包头也写它，或者用更大的 `revision` 替换它的包 | 给每个来源的目录配了各自的系统写权限才防得住 | 每个来源用自己的系统用户跑，只能写自己的目录。这是部署的事，模块不管 |
| 几个打包方跑在同一个系统用户下，其中一个故意冒充 | 防不住 | 系统权限分不开它们，谁都能写谁的目录，这时目录分开只防手误 |

第一版如果都跑在同一个系统用户下，就靠部署保证只有可信的打包方能写收件目录。对外之前要给每个来源分开系统用户。

**新来源接入：**

1. 在登记表加一行，`env` 先写 `test`。
2. 建目录：`inbox-test/<source>/` 和它下面的 `.tmp/`，还有 `failed/<source>/`。系统权限按上面的表配：来源目录只有这个来源和 javmem 能写，`failed/<source>/` 只有这个来源能读。
3. 按规范打 5 个样包，投 `inbox-test/<source>/`，全部通过校验。
4. 抽查样包：原话和聊天记录逐字对得上，时间和说话人齐全，外部内容标了，该打码的打了。
5. 连续 3 天没有失败包，再把 `env` 改成 `prod`，建 `inbox/<source>/` 和它下面的 `.tmp/`，投正式目录。
6. 上线第一周，巡检重点看这个来源的包。

## 12. 巡检

模块提供一个检查，多久跑一次由部署方定。有下面这些情况就提醒：

- `failed/` 里有失败包，按来源目录报。`failed/_unknown/` 里有文件，说明有程序没按来源目录投。
- 处理任务太久没跑。多久算太久写在配置里，默认 26 小时。
- 抽取失败的包。重投会被去重跳过，要用管理命令重跑抽取。
- 同一个来源的 `daily` 包，时间段合起来有缺口，可能漏了一段。按权限拆开的包时间段相同不算问题，`adhoc` 和 `backfill` 不算。
- `revision` 相同、内容却不一样的包（第 10 节）。
- 撤回过的包号又来了（第 10 节）。
- 收件时记下的警告：认不出的标题、写错的附件块（第 3 节）、解析不了的行、认不出的行、时间倒退（第 5 节）。
- 打码模式表命中的包（第 7 节）。只报包号和类型，不抄值。
- 来源目录里有不是 `.md` 的文件，或者 `.tmp/` 以外的子目录。这些不会被收。

## 13. 包头怎么变成查询过滤

包头这几个字段决定查询时谁看得到这个包。规矩的全文和例子在 [query-api.md](query-api.md) 第 3 节，这里是同一张表：

| 包头 | 入库时变成 | 查询时怎么用 |
| --- | --- | --- |
| `env` | 进正式库还是测试库 | 身份的 `env` 决定查哪个库，工具没有选库的参数 |
| `domain` | 整包的分区 | 包的分区里至少有一个在身份的 `partitions` 里 |
| `sensitive` | 整包的敏感标记 | 包的每个标记都要在身份的 `sensitive` 里 |
| `privacy: private` | 整包多一个保留标记 `private`；处理时不走云上的模型，没配本地模型就只进原文层，不抽取 | 和敏感标记一样：身份的 `sensitive` 要写明 `private` 或 `"*"` |
| `privacy: normal` | 不加东西 | 不影响过滤 |

这些都是包一级的，分区和敏感标记合起来叫这个包的可见范围。处理线不跨可见范围：不同范围的包不放进同一个窗口，它们的事实和关系也不合并成一条。

分区和敏感标记的算法不一样：分区有一个能看就过，敏感标记每个都要能看。财务、投资的严格规则另算，不看身份：包的分区里只要有一个是严格分区就触发。
