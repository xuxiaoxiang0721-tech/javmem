# 安全

javmem 在安全上做到哪、信任谁、删到哪、哪些删不到要自己管。怎么摆、怎么配见 [deploy.md](deploy.md)。

## 1. 查询服务和身份（信任边界）

- **只走本机 stdio，不开端口。** `javmem serve` 由 Bot 的 MCP 客户端起，一行一条 JSON-RPC。查询服务的模块里不许有开端口、起网络服务的写法，`tests/test_query_no_ports.py` 钉着；要开网络连接，得先加鉴权、改这一份。
- **身份靠部署，不靠鉴权。** 身份是启动时的环境变量 `JAVMEM_CALLER`，由部署的人写进 Bot 的 MCP 配置。谁能看什么写在 `JAVMEM_ACCESS_FILE`，每次调用都按最新的算。没设身份、身份不认识、配置读不了的，每一次调用都拒（`unknown_identity`），一条内容都不给；工具清单照样列得出来，好让客户端连得上、看得到错在哪。
- **五个查询工具都是只读的。** 撤回、冻结、处理待确认、重建主图这些管理操作是命令行的命令，不是查询工具，Bot 调不到。
- **这一版防不住的：** 查询服务跑在 Bot 的系统用户下。Bot 要是改得了自己的 MCP 配置，就能换一个身份；它读得到数据目录，就绕得过所有过滤。所以现在只给信得过的 Bot 用（比如都是主人自己的 Bot），MCP 配置、身份配置由部署的人写、Bot 改不了。要给信不过的 Bot 用，得等查询服务能跑在 javmem 自己的系统用户下（走本机的网络连接、每个身份一个令牌），现在没有。
- **实体编号是照名字算的（没加盐）。** 拿到编号的，能离线一个个试名字（猜一个它看不到的全名，算一下对不对得上）。在上面这个信任边界里 Bot 本来就读得到账本，所以这一版不处理，等查询服务能单独跑的时候一起改。
- **看不到的和不存在的长得一样。** 过滤在检索之内：看不到的内容不影响命中、排序、数量和候选名单，也不会说“有东西被滤掉了”。

## 2. 一套只放一个主人

- 一套 javmem（一个数据目录、一个查询服务、一张主图）只放一个主人的记忆；几位主人就几套，数据目录、配置、主图、系统用户、端口各是各的（[deploy.md](deploy.md) 第 1 节）。
- 做了防串的：一个查询身份只对一个库（正式库或测试库）；主图、Graphiti 支线的图里都放着防串库的标记，认不出来的一个字不写；主图和测试图不能是同一个地址。
- 没做、要部署的人管的：几套共用 L3 结果库、向量缓存（`--store`、`--vectors` 指到同一处）不拦，别这样用；几套之间靠系统用户、目录权限分开。

## 3. 来源和投包

- 只有来源登记表里的来源能投包；收件时核对目录和包头，对不上的拒收、写回执。要防一个来源冒充另一个，每个来源用自己的系统用户、只能写自己的收件目录（[deploy.md](deploy.md) 第 2 节）。
- 邮件、附件、包里标成外部的内容都当转述，不当事实；外部内容后来说的值不替代主人原话说过的值，进待确认等主人定。夹带指令的包（“忽略上面的规矩……”）不起作用：投毒演练 `javmem drill poison` 专门试这些。
- 附件里的 PDF、Excel、Word 在子进程里读：一个文件 60 秒到点就停，子进程最多用 2 GB 内存（Linux、macOS 上子进程自己限，Windows 上放进作业对象），文件超过 20 MB 不打开，读到 2 万字就停。

## 4. 撤回、彻底删除管到哪

`javmem withdraw` 按包或者单条（一条事实、一句原文）撤回；`javmem purge` 把撤回了的包彻底删除。两样都要先拿收件、写账、L3 结果库三把锁，中途断了不写目标再跑一次接着清。

| 哪一层 | 撤回 | 彻底删除 |
| --- | --- | --- |
| 原文层 | 包、句子标上撤回，查询、处理线都不再用；别的包里引用它的行一起标上 | 归档文件、跳过的副本、原文句都删掉，只留指纹（以后到的引用还认得出） |
| 账本 | 出自它的说法、事实、关系、别名、实体、待确认、隔离都删；别的来源也支持的照剩下的证据重算；冻结的先藏起来、进待确认 | 同左，再整理文件（删的时候抹成 0、`VACUUM`、清日志） |
| L3 结果库 | 用过它的窗口（拿它当上文的、同一往来串一起写的、标注用了从它学来的名字的）和结果都删，那些包改回排队重抽 | 同左，再整理文件 |
| 向量缓存 | 事实、说法、关系都不再用的文字删掉 | 同左，再整理文件 |
| 软变化判定（`soft/soft.db`） | 题里、回复里带着撤回句子的判定整条删 | 同左，再整理文件 |
| 主图（Neo4j） | 当场同步：删掉的不在图里 | 同左；社区版磁盘上可能还留着，见第 5 节 |
| Graphiti 支线的图 | 这个包的那几组整组删；连不上的先删本机的原文、记待清，下次连上先删 | 同左；社区版磁盘上可能还留着 |
| 备份 | 恢复时照撤回清单再删一遍 | 同左；旧备份里还在，见第 5 节 |

每月做一次删除演练（`javmem drill delete`，在拷贝上做）：撤回一个包、再彻底删除，逐层查、逐字节搜，看是不是真删干净了。

## 5. 删不到的、要自己管的

- **已经发给模型的内容：** 抽取、核对、判断时窗口里的原文发给了你配的模型，那边留多久、拿不拿去训练归服务商的条款管，javmem 删不到。不想发出去的，包头写 `privacy: private`（没配本机的模型就只进原文层）。
- **Neo4j 社区版的磁盘：** 删掉的点和边，存储文件、事务日志里可能还留着。要干净就换一张新图：停容器、删它的数据目录、重起、`javmem graph init`、整张同步（主图能从账本整张重建）。
- **旧备份：** 删掉的东西在之前的备份里还在，旧备份到期才没；真要“今天就删干净”，手动删掉那天以前的备份（历史版本也就没了）。
- **你自己导出、拷走的：** `javmem export-facts` 导出的文件、回归跑分和演练的工作目录、`javmem soft judge --store` 放在数据目录外的判定，都要自己删。
- **别的包里一字不差、但不是引用的句子**（转发、别人又说了一遍）：撤回不跟着撤，8 个字以上的列在撤回报告的 `copies_elsewhere` 里，要人看一下，要撤就再点它们。
- **几种很偏的情况：** 结果库里已经没有某个窗口时（删过结果库、整本重建导进来的旧账本），有几种隔离行、整包撤回认不出来，要等那个包下次重写才清。

## 6. 密钥和打码

- 模型、向量服务、图的密钥、密码只放环境变量；javmem 不打印、不写文件、不放进命令行参数，报错里也不带。配置文件里没有密钥。
- 包里的密码、验证码这类由打包方打码（`[已隐去:…]`）；发给模型以前，javmem 照打码规则把每一行、拼起来的每一行再扫一遍，还扫得出来的那个窗口不发。
- 查询、命令的日志、报告里只记种类、编号和数，不记原话和查询词。

## 7. 发现安全问题

请私下告诉维护的人（照仓库主页上写的私下报告的办法），别开公开的 issue。说清楚怎么复现、影响到哪一层；能给编的样例最好，别附真实的记忆包。
