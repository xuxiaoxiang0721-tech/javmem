# 校准：在自己的数据上量准 javmem

javmem 抽得准不准，要在你自己的数据上量。先后是：**先跑演示看懂打分 → 拿自己的十来个包做一份金标准、打分 → 平时看不用金标准的四个数 → 改提示词、换模型以前和以后，拿金标准和自己的题各量一次。** 这些工具都不调模型（只有抽取本身要调）；只有可选的 `javmem quiz`（让模型照查到的答题、判分）要调模型、花钱。

| 做什么 | 命令 | 说明 |
| --- | --- | --- |
| 看一遍整圈 | `javmem demo --to 新的空目录` | 编的数据，不要密钥 |
| 出金标准的草稿 | `javmem gold prelabel` | 照账本里已经抽出来的出，给人审 |
| 一条一条审 | `javmem gold review` | 一页本机打开的网页：对、错、改，补漏了的 |
| 核金标准写得对不对 | `javmem gold check` | 出处、名字、类型、关系、日子精度 |
| 打分 | `javmem score` | 拿金标准给一份抽取结果打分 |
| 不用金标准的四个数 | `javmem selfcheck` | 两遍一样不一样、证据找得到的比例、合在一起对不上的、一样东西几个名字 |
| 拿题量检索 | `javmem regress` | 证据命中率，见 [questions.md](questions.md) |
| 让模型答题、判分（可选） | `javmem quiz` | 要调模型、花钱；先 `--dry-run`，见 [questions.md](questions.md) 第 4 节 |

标什么、怎么认见 [definitions.md](definitions.md)（定义卡），金标准的文件怎么写见 [gold-format.md](gold-format.md)。

## 1. 先跑演示，看懂打分

```bash
javmem demo --to 仓库外一个新的空目录
```

演示照录好的回复走一整圈，第 5 步拿编的金标准打分，第 6 步出不用金标准的四个数。打分的六个主要的数：

| 数 | 意思 |
| --- | --- |
| 关系准确率 | 抽出来的关系里，主体、关系、客体都对得上金标准的 |
| 关系覆盖率 | 金标准的关系里，抽到了的 |
| 变化判对率 | 金标准的变化（以前是什么、后来改成什么）里，javmem 判出来了的 |
| 别名对齐率 | 金标准的别名里，认到了对的那个实体上的 |
| 事实完整抽到 | 金标准的事实里，主体对、值和数都抽全了的 |
| 事实对得上 | 抽出来的事实里，对得上金标准某一条的 |

## 2. 做一份自己的金标准

挑**十来个**自己的包就够：有改过主意的、换过人的、有数的、有亲属和公司关系的，各种都有一些。这些包要已经抽完、写进账本（`javmem extract`、`javmem write`）。

1. **出草稿**（照 javmem 现在抽出来的，**不是标准答案**）：

   ```bash
   javmem gold prelabel --library test --packet 包号 --packet 包号 … --unit D1 --out 仓库外的新目录
   ```

2. **一条一条审：**

   ```bash
   javmem gold review --gold 那个目录 --out 仓库外/审阅.html
   ```

   用浏览器打开，每条点“对”“错”“改”，错的、改的写一句为什么；漏了的在每个单元最后“补一条”。审到一半关了，浏览器记着进度；点“存下来”得到 `审阅.json`。下次接着审：`--review 审阅.json`。每一条都要看：草稿是 javmem 自己抽的，不审直接拿来打分，分数一定好看，没有意义。

3. **改成结构：** 改了的、补的只有一句话的，打分时先单列、不算分。照 [gold-format.md](gold-format.md) 把它们写成条目（直接改单元的 JSON，或者在审阅结果里带上改好的整条），再核一遍：

   ```bash
   javmem gold check --gold 那个目录 --library test
   ```

   只打条目编号和哪一种不对，不抄内容。

4. **打分：**

   ```bash
   javmem score --gold 那个目录 --review 审阅.json --side javmem=数据目录 --library test --out 仓库外的新目录
   ```

   输出目录里有每一条对不对、为什么；里面有原话，放在仓库外。

金标准做好了别改着玩：每次量都拿同一份比，改了就和以前的分数比不了。要改，另存一版。

## 3. 平时看四个数（不用金标准）

```bash
javmem selfcheck --library test
```

| 数 | 看什么 |
| --- | --- |
| 两遍一样不一样 | 同一版提示词、同一个模型抽两遍，内容一样的有多少。低了说明模型不稳：同一句话这次抽出来、下次抽不出来 |
| 证据在原文里找得到 | 抽出来的事实、关系，引文在原文里逐字找得到的有多少。低了说明模型在编引文 |
| 合在一起又对不上的事实 | 几处说法合成一条的，日子、编号、金额却对不上：可能是两件事被当成了一件 |
| 一样东西几个名字 | 落在合并提议里的实体有多少：同一个人、同一家公司被拆成了几个 |

**两遍：** 另建一个数据目录（`JAVMEM_DATA_DIR` 换一个），同样的包收一遍、`javmem extract` 抽一遍（要调模型，挑十来个包就够），再比：

```bash
javmem selfcheck --library test --runs 原来的数据目录 新的数据目录
```

输出只有数和编号。要看是哪几条：事实 `javmem audit --library test --item 编号`，提议 `javmem entities --library test --show 编号`。

## 4. 改提示词、换模型

抽取的提示词在 `src/javmem/pipeline/prompts/`，带版本号；用哪一版看 `JAVMEM_L3_PROMPT`（不写的用默认的 `l3-v17`），模型看 `JAVMEM_LLM_*`。每一版的指纹钉在 `javmem.pipeline.extract.PROMPTS` 里，旁边的注释写着它从哪一版改来、多了什么。

- **换一版现成的：** 先拿你那十来个包另建一个数据目录，用新的那一版抽一遍、写进账本；金标准打一次分、`javmem regress` 量一次题、`javmem selfcheck` 看一次（想看答得对不对的，再用 `javmem quiz` 答一遍、判一遍，花钱），都不比原来的差再换。
- **自己改提示词：** 拷一份成新的版本号（不在老的上改：老的版本号对着存下来的结果），在 `PROMPTS` 里登记它的指纹，跑一遍测试，再照上面量。改了“算什么、不算什么”的，[definitions.md](definitions.md) 也要跟着改（有测试拿它的几张表对着代码里的清单核）。
- **记下来：** 每次量完记一行：哪天、哪一版提示词、哪个模型、金标准的六个数、题的命中率、四个数。以后才知道是哪一步变好、哪一步变坏的。

要比的时候，`javmem regress` 的套件里两版各写一条线（各配自己的结果库），一遍量完。
